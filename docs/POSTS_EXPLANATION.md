# Модуль posts

Посты пользователей: создание, чтение, правка, удаление. Образец — пример с продуктами из документации по авторизации.

## Файлы

| Файл | Роль |
| --- | --- |
| `entities/post.entity.ts` | Таблица `post` |
| `dto/create-post.dto.ts` | Тело `POST /posts` |
| `dto/update-post.dto.ts` | Тело `PATCH /posts/:id` (любое подмножество полей создания) |
| `post.policy.ts` | Правила доступа |
| `posts.service.ts` | Работа с БД и проверка прав |
| `posts.controller.ts` | HTTP-маршруты `/posts` |
| `posts.module.ts` | Подключает репозиторий, сервис и политику |
| `post.policy.spec.ts` | Тесты политики |
| `posts.controller.spec.ts` | Проверка, что контроллер создаётся |

## Как это работает

### Сущность

`content`, `published`, `authorId`, `createdAt`. `published = false` означает черновик. `authorId` вынесен в отдельную колонку, чтобы политика сравнивала `post.authorId` с `user.id`, не загружая связь. При удалении автора его посты удаляются каскадом.

### Политика

| Способность | Правило | Тип `user` |
| --- | --- | --- |
| `view` | опубликован или пользователь — автор | `User \| null` |
| `create` | пользователь вошёл | `User \| null` |
| `update`, `delete` | пользователь — автор | `User` |

`User | null` означает, что способность работает и для гостей. Это обязательно для `create`, потому что она проверяется на маршруте, и для `view`, потому что гости читают посты. `update` и `delete` вызываются только из сервиса для вошедших, поэтому `null` там не нужен: компилятор не даст передать гостя.

### Где проверяются права

- **`POST /posts`**: проверка на маршруте (`@Can(PostPolicy, 'create')`), потому что она не зависит от записи. Гость получает 401 от аутентификации ещё до политики.
- **`GET /posts`, `GET /posts/:id`**: `@Authenticate({ optional: true })` и `@Can.Anyone()`. Без `optional` гость получил бы 401. Права решает сервис.
- **`PATCH` и `DELETE`**: `@Can.Anyone()`, права решает сервис, потому что нужен загруженный пост.

Без объявления на маршруте глобальный гвард его закрыл бы, поэтому `@Can.Anyone()` стоит там, где проверка вынесена в сервис.

### Сервис

- `create` — сохраняет пост, автор берётся из текущего пользователя, а не из тела запроса.
- `findAll` — **список фильтруется в запросе**: опубликованные посты плюс собственные черновики (для гостя только опубликованные). Политика проверяет одну запись, а загрузка всех постов с проверкой каждого ломала бы пагинацию и тянула лишние данные.
- `findOne`, `update`, `remove` — загружают пост (нет поста → 404), затем `authorize()`. При отказе гость получает 401, вошедший пользователь 403.

Проверка в сервисе, а не в контроллере, даёт одинаковые правила для любого вызывающего кода: HTTP, очередь, другой модуль.

### DTO

`CreatePostDto`: `content` (непустая строка) и необязательный `published`. Валидацию выполняет глобальный `ValidationPipe`. Автора в DTO нет.

## Ограничения

- Пагинации нет: `GET /posts` возвращает все подходящие посты.
- Модерации нет: роли не заведены, чужой пост не удалить даже администратору.
- Проверялись только компиляция и юнит-тесты политики. Маршруты вручную не вызывались, миграция не применялась.
